# CDTL3 (Cooldown Timeline 3) — CLAUDE.md

Tracks cooldowns as icons along a timeline. **Continuation** of Cooldown Timeline
(original by Vreenak, v2 rewrite by cliffclive), patched for **Midnight 12.x** and
continued by Nelnamara. Repo folder is `cdtl3-dev`; the deployed AddOn folder is
**`CooldownTimeline3`**. AceAddon-based.

## Naming: fully `CDTL3` (rename complete)
The object, AceAddon name, AceConfig table keys, frame names, and Masque group are all `CDTL3` now (formerly `CDTL2`). The saved DB is **`CDTL3DB`**, migrated from the old `CDTL2DB` in `OnInitialize`:
`if not CDTL3DB and CDTL2DB then CDTL3DB = CDTL2DB end` (before `AceDB:New("CDTL3DB", ...)`).
The TOCs declare **both** (`## SavedVariables: CDTL3DB CDTL2DB`) so the old global still loads for that one-time migration — drop `CDTL2DB` from the TOC in a future version. The lowercase `/cdtl2` slash stays as a legacy alias. **Do not reintroduce uppercase `CDTL2`** except that TOC migration declaration.

New characters: `db.global.newCharacterProfile` (nil = Default, LAST, CHOSEN) + `lastProfile` (never a zone profile). Harnesses `tools/tests/anchors.lua`, `profiles.lua`.

- `Flights.lua` (since 3.1.1; loaded after CombatTimers.lua, after its `FlightData` file): flight timers (`CDTL3.Flights`). `TAXIMAP_OPENED` caches the taxi map (slot name/type, node ID from `C_TaxiMap.GetAllTaxiNodes(GetTaxiMapID())` by `slotIndex`, hops from `GetNumRoutes`/`TaxiGetNodeSlot`). A `TakeTaxiNode` post-hook picks the route, and polling `UnitOnTaxi` times takeoff and landing. One reused cooldown of type `flights` (Cooldown.lua counts it down; `FL:Hold` keeps it at 0.1 s until landing). Learned times go in `db.global.flightTimes[client]` (routes `"from-to"` node IDs, plus the yards and seconds that fit the speed); the flight in the air goes in `db.char.flight` for a resume. Estimates = route yards from `FlightData/<client>.lua` ÷ speed (30.3 yd/s until fitted) + stop seconds; with no data, straight map lines × 1.2. Flights are exempt from Hide Long Timers (`IconUpdate`) and from Hide out of combat (`FL:Holds` in `CDTL3:Autohide`). `profile.tables.flights` stays empty so lookups by type find nothing. **Flights that don't start from the taxi map** (a chat option like the druids' Bunthen Plainswind / Silva Fil'naveth, a quest, a spell): a `C_GossipInfo.SelectOption` post-hook or `PLAYER_CONTROL_LOST` starts a 10 s takeoff watch; the takeoff point = nearest `flightData.nodes` point within 150 yd (other faction's skipped); route = `starts[how it started]` (learned) else the one data route from that point; landing's nearest point fixes and learns the route. `FL:Hold`/`FL:Holds` act only while a countdown runs (a flight can have none). Spec: `docs/flight-timers-spec.md`.

## Multi-version TOCs (all must agree on SavedVariables)
`CooldownTimeline3_Mainline.toc` (Interface 120105 = 12.1.5; per warcraft.wiki.gg any mismatch with the client's number is "out of date", so bump it every retail patch), `_Mists` (50504 = MoP Classic 5.5.4),
`_TBC` (20506 = TBC Anniversary 2.5.6), `_Vanilla` (11509 = Classic Era 1.15.9), `_Camelot` (16001 = WoW: Forever 1.60.1), and an unsuffixed **`CooldownTimeline3.toc`** (16001) as the Forever fallback. The Forever beta loads `_Camelot.toc` then the plain `.toc` — it does **not** fall back to `_Mainline.toc` (tried in 3.0.8 dev; addon didn't appear in the list). `_Camelot` "may change before launch", hence the plain fallback. The packager reads X-Curse-Project-ID/X-Wago-ID from the unsuffixed TOC first, so keep those in it; BigWigs packager ≥ v2.6.0 maps `16xxx`/`_Camelot` to CurseForge's Forever game version. All six declare **`## SavedVariables: CDTL3DB CDTL2DB`** (CDTL3DB = live, CDTL2DB = legacy kept for the migration). They must stay identical across all six — a mismatch silently wipes that client's profiles (the Classic TOCs once had the wrong name and did exactly that). **Packager rule:** a comma-separated `## Interface:` list is fine, but a suffixed TOC may only carry numbers of its own game type — BigWigs packager v2 fails the whole release on e.g. `120105, 16001` in `_Mainline` (checked in 3.0.12 against its real parser). The wiki ranks the `_Mainline` family suffix above the plain `.toc` for Forever (contradicting the 3.0.8 beta test); `_Camelot` matches today and `_Forever` is a listed alias, but the packager only knows `_Camelot`.
File lists: every TOC loads `Presets.lua` (after Media.lua) and `EditMode.lua` (after Cooldown.lua). **`Libs\LibEditMode\embed.xml` is listed in every TOC except `_Vanilla`** — the library assumes `EditModeManagerFrame` exists and errors at load without it (Classic Era had no Edit Mode; EditMode.lua returns early when the library isn't loaded). Per warcraft.wiki.gg, Era **1.15.9 now has Edit Mode** — adding LibEditMode to `_Vanilla` is untested and not done yet.

## Midnight gotchas
- `Settings.OpenToCategory("CDTL3")` (string) **errors** on Midnight — use `LibStub("AceConfigDialog-3.0"):Open("CDTL3")` (the slash + minimap button do this).
- **Cooldown values are SECRET when tainted.** `C_Spell.GetSpellCooldown(id).startTime`/`.duration` can be *read* without error, but **comparing or doing arithmetic on them throws** ("attempt to compare a secret number value"). Both `Helpers.lua:GetSpellCooldown` **and** `GetSpellCharges` do the comparison **inside** a `pcall` and only return real numbers (GetSpellCooldown falls back to event-tracked cast time + `GetSpellBaseCooldown`; GetSpellCharges falls back to 0s). Never compare/use these outside the protected closure (the GetSpellCooldown form was the v3.0.4 fix — Lane view spammed 167× before; GetSpellCharges was hardened the same way to prevent the twin crash on charge-based CDs).
- **Textures must be `.tga`, not `.png`, on Midnight.** PNGs render as the missing-texture checkerboard on 12.0.x — the addon ships `.tga` and the `.png` files are kept only as source art. IconTexture → `Media\icon-128.tga`; minimap button texture → `Media\minimap.tga`. (v3.0.5 fix.)
- **Hidden sizes on bordered icons (GitHub issue 9, fixed in 3.2.2).** A frame anchored to a combat timer's bar fill, and anything anchored to that frame, reads its size and position hidden (`GetWidth`/`GetHeight`/`GetSize`/`GetRect`/`GetCenter` are `SecretWhenAnchoringSecret` in Blizzard's API docs), and the game only works that out on its layout pass, so it still reads hidden in the frame the icon leaves the bar. Blizzard's BackdropTemplate does maths on `GetWidth()` in `SetupTextureCoordinates` (Backdrop.lua 221-226, called from SetBackdrop and OnSizeChanged), which threw on every bordered riding icon from 3.1.0. `CDTL3:SetBorder` (Helpers.lua) keeps one backdrop table per border while its settings are the same (SetBackdrop returns at once for the table it has), and where `IsAnchoringSecret` exists gives each border frame its own `SetupTextureCoordinates` that waits while the size is hidden and tiles from a one-shot OnUpdate once it reads plain. Never read a riding icon's size or position outside a pcall. Harness: `tools/tests/combattimers.lua` section 2b models Backdrop.lua and the layout pass.
- **Midnight reports the *base* cooldown, not the talented one** — `C_Spell.GetSpellCooldown(id).duration` strips talent reductions (e.g. Bestial Wrath shows 90s, not the talented 30s). The per-spell **Custom CD Time** override (Filters) lets users correct this; it must win over the live duration. The v3.0.6 fix stopped the live value from silently overwriting the override every frame.

## WoW: Forever gotchas (3.0.8)
- **Forever = modern Mainline engine + vanilla-era interface number (16xxx).** `CDTL3.isForever` keys off the **16xxx interface band** — `WOW_PROJECT_ID` was Mainline (1) on early beta builds but became **18** in build 70205, so never detect Forever by project ID alone. The old globals (`GetSpellInfo`, `GetSpellCooldown`, `GetSpellCharges`, `UnitAura`, `GetNumSpellTabs`…) are gone, and Midnight secret values apply. So **never gate an API call on `tocversion >= 110000`** — use **`CDTL3.retailAPI`** (CDTL3.lua top; true on retail and Forever). `CDTL3.tocversion` stays for era *content* only (Data.lua spell lists, class-colour pickers, test icons), where Forever correctly behaves as Vanilla. `CDTL3.isForever` for Forever-only exceptions (e.g. SoD `RUNE_UPDATED` doesn't exist there).
- **Deprecation fallbacks only cover what Retail still has.** Forever, like every client, loads Blizzard's `Blizzard_Deprecated*` addons while the CVar `loadDeprecationFallbacks` is on (the default on all five; checked 17 Nov 2026 in each client's UI source and CVar list, which corrects an older note here that Forever ships none), but a global Blizzard removed outright is nil (first hit: `GetItemSpell`, nil on Forever and removed outright in 12.1.5), and a player can turn the fallbacks off. Call **`CDTL3.Compat.GetItemSpell / GetItemInfoInstant / IsSpellKnown / IsSpellKnownOrOverridesKnown`** (CDTL3.lua top), never the bare globals. Before using any other old global, check its warcraft.wiki.gg page for a `deprecatedapi` tag and run `tools/luals-check`. `ActionButton_Show/HideOverlayGlow` are existence-guarded (GLOW style falls back to BORDER).
- **Ace3 must be current** — bundled Ace3 is **r1403** (from `https://repos.wowace.com/wow/ace3/tags/`, `svn export` the 10 Ace/CallbackHandler/LibStub folders into `Libs/`). The pre-r1403 copy errored on Forever (`SetDesaturation` nil in CheckBox, `tooltip:SetText(..., true)` alpha). The nested `Libs/AceGUI-3.0-SharedMediaWidgets/Libs/` copies are NOT loaded (widget.xml only includes the widget files).
- **Combat log is closed to addons on Forever AND on retail 12.x** — `COMBAT_LOG_EVENT_UNFILTERED` is registered only when `not CDTL3.retailAPI` and `CombatLogGetCurrentEventInfo` exists, inside a `pcall`, so a refusal can't abort the rest of `TurnOn`. Retail still has the deprecated function, so an existence check alone registered it there (fixed 3.0.12); `CDTL3.combatLogRegistered` is forced `false` at load on retailAPI clients so `NoCombatLog()` hides the dead options even with detection off. Player buff/debuff discovery + custom aura triggers live in **`CDTL3:OnPlayerAuraApplied`**, fed by both CLEU `SPELL_AURA_APPLIED` and **`UNIT_AURA`** (registered on `retailAPI` clients: `addedAuras`, plus `updatedAuraInstanceIDs` — a recast of an existing buff is an update, not an add — plus a full `GetAuraDataByIndex` scan on `isFullUpdate` (login//reload/zoning); accessors and field reads all inside pcalls because they can be secret; login full update often arrives before `GetPlayerInfoByGUID` works, so UNIT_AURA returns early while `CDTL3.player.guid` is nil and OnEnable's 5s timer rescans via `CDTL3:UNIT_AURA("UNIT_AURA", "player")`; OnPlayerAuraApplied claims an existing saved entry for the current character (`AddUsedBy` with the entry's own id) whenever the aura is seen — Filters lists only entries whose `usedBy` holds the current GUID, and 3.0.8-dev builds had saved ownerless entries) with a 0.5s same-aura dedupe (`CDTL3.recentAuras`). Still CLEU-only, so dead on Forever: **offensive** auras (debuffs on enemies) and the **swing timer**.
- **Secret values beyond cooldowns (Forever)**: player `UnitHealth`/`UnitPower` (current), `UnitAttackSpeed`, item cooldowns, aura data AND the `UNIT_AURA` payload itself (`updateInfo.isFullUpdate` is a secret boolean in combat) can all be secret. Patterns in use: Lanes.lua `private.Fraction` / `BarValueDiffers` (CalcTracking returns `0, current, max` when secret and LaneUpdate feeds the StatusBar via `SetMinMaxValues`/`SetValue`, tracked by `f.secretRange`); Helpers.lua `CDTL3:GetItemCooldown` / `GetInventoryItemCooldown` (nil when secret — callers skip the refresh); tick handlers and Data.lua tag converters run inside pcall (tag → `?`). Never compare/do arithmetic on a unit or cooldown value outside a pcall.
- Beta install path (folder name must be exactly `CooldownTimeline3`, not a GitHub zip's `cdtl3-dev-<branch>`): `World of Warcraft\_classic_beta_\Interface\AddOns\CooldownTimeline3\`; the launch client lives in **`World of Warcraft\_forever_\`** (wago product `wowf`, build 1.60.1.70707 on 2026-10-30). Forever launched 2026-11-04 on 1.60.1 (interface 16001; the wiki's 1.60.1 entry lists the `_Camelot` game type with `_Forever` as an alias).

## Slash
`/cdtl3` · `/cooldowntimeline3` (primary) · `/cdtl2`, `/cooldowntimeline2` (legacy aliases). ## Config architecture (3.0.7)
- **All settings live in ONE movable AceConfigDialog window**: `CDTL3:GetFullOptions()` (Options.lua, bottom) = GetMainOptions + the Lanes/Ready/BarFrames/Filters tables + `CDTL3.profile` embedded as tabs (orders 2001–2005, args keys `lanes/ready/barFrames/filters/profiles` — the `/cdtl3 <tab>` slash subcommands SelectGroup on those keys). Registered as `"CDTL3"` in **both** OnInitialize (CDTL3.lua) **and** `RefreshConfig` (Helpers.lua ~1231) — the RefreshConfig re-registration MUST use GetFullOptions or a profile switch strips the tabs.
- **Blizzard's AddOns settings entry is a launcher only** (`"CDTL3Bliz"`, one button → `AceConfigDialog:Open("CDTL3")`), because Blizzard's Settings frame is unmovable. Do NOT re-add child AddToBlizOptions panels — settings hidden there was why users couldn't find the lane/bar color pickers (the 2026-08 CurseForge "add bar colors" request was an access problem, not a missing feature).
- **12.1 aura secrecy**: `AuraExists` (Helpers.lua) does its whole scan + name compare + duration math INSIDE one pcall (same idiom as GetSpellCooldown/GetSpellCharges) and returns nil while auras are secret (combat/encounter/M+/PvP). Aura-triggered tracking degrades gracefully there — that's the best possible without the (display-only) AuraContainer system.
- **Dynamic Color** (off by default): per bar-frame `bar.dynamicColor {enabled, warnTime, warnColor, readyColor}` in `barFrameDefaults` (CDTL3.lua); blend applied in `private.UpdateBarDynamicColor` from `private.BarUpdate`; base color resolution factored into `private.GetBarFGColor` (school → class → frame), shared with RefreshBar.

## Structure (3.0.8)
- **Defaults**: lanes, bar frames and ready frames are each declared **once** in CDTL3.lua (`laneDefaults`, `barFrameDefaults`, `readyDefaults`, just above `local defaults`); `lane2`/`lane3`, `frame2`/`frame3`, `ready2`/`ready3` are `WithOverrides(base, { only the values that differ })`. A new per-lane/frame setting goes in the base table only. When restructuring defaults, deep-compare the old and new tables (the 3.0.8 refactor was verified that way).
- **Lane, bar frame and Ready frame by number**: `CDTL3:SlotSettings(group, n)` (`group` = `lanes`, `barFrames` or `ready`) gives `CDTL3.db.profile[group]["lane1"]` and so on, read from the live profile, and `CDTL3:SlotFrame(group, n)` gives `CDTL3_Lane_n` / `CDTL3_BarFrame_n` / `CDTL3_Ready_n` (CDTL3.lua top). Only 1, 2 and 3 have a slot; anything else gives nil. Use them instead of an `if i == 1 … elseif i == 3` chain (17 Nov 2026: those chains were ~900 of the WoW API check's warnings). `CDTL3:SlotOfParent(name)` answers which slot holds a timer from its icon's or bar's parent frame name (icons sit in `CDTL3_Lane_n`, bars and ready icons in `CDTL3_BarFrame_n_MF` / `CDTL3_Ready_n_MF`), and `CDTL3:SlotParent(group, n)` gives that frame. Harness `tools/tests/slots.lua`.
- **Shared pieces (17 Nov 2026 copied-code cleanup; add to these, never copy a block again).** `private` is a separate table in each file (`local private = {}`), so cross-file sharing is a `CDTL3:` method.
  - Bar frames and Ready frames: `CDTL3:CreateStackFrame` / `RefreshStackFrame` / `StackChildren` (BarFrames.lua; the cell size and padding per kind in `private.CELLS`).
  - Show and hide (`showAnim` / `hideAnim` per lane, bar frame and Ready frame, defaults `ShowAnim` / `HideAnim` in CDTL3.lua; options `private.AddShowHideArgs`): `CDTL3:SetFadeAnimations(f, alpha, s)` keeps one group per direction (`f.animateIn` / `f.animateOut`), one Alpha (and Scale) animation per loop, rebuilt only when type, loops or bounce change; the group's OnFinished leaves the frame at its resting alpha.
  - All three frame kinds: `CDTL3:SetFadeAnimations` and `CDTL3:FinishFrameRefresh` (Lanes.lua). The Fight Timeline and Ready board share `CDTL3:RidingTimeLeft` (FightTimeline.lua).
  - Cooldown.lua: `private.RefreshTexts` (icon and bar texts 1 to 3), `private.CreateUnlockBox`, `private.SpellCountdown`, `CDTL3.CalcSplitPosition`.
  - CDTL3.lua: `CDTL3:ShowKnownSpell` (the cast handler and `ScanCurrentCooldowns`), `private.PanelBackground`, and the defaults' `ICON_TEXT` / `MODE_TEXT` / `FRAME_BACK` bases. IconFx exports `Ring` / `RingShow`, which Group.lua's Burst strip uses.
  - Harnesses `cdparts.lua`, `dedupe.lua` and `framedump.lua`. To prove a refactor of defaults, frames or options changed nothing, diff `defaultsdump.lua`, `framedump.lua` or `optionsdump.lua` output from the old and the new code.
- **New saved entries**: always build them with the Helpers.lua helpers at the top of the file — `ApplyEntryDefaults(s, type)` (per-type Filters → Defaults + `usedBy` = this character), `IgnoredByDefault(type, bCDms)` (ignored when ≤3s or over the type's Ignore Threshold, inclusive), `NewSpellEntry`, `NewItemEntry` (`icon` = use-spell icon, `itemIcon` = item icon), `SaveNewEntry(s, type)` (inserts, then creates the icon unless ignored/type disabled; returns the frame). `private.CarriedItemIDs()` = equipped slots 0–23 then bags 0–4. Thirteen hand-copied builders had drifted before 3.0.8.
- **Unit events** (`UNIT_SPELLCAST_SUCCEEDED` player+pet, `UNIT_AURA`, `UNIT_POWER_FREQUENT`, `UNIT_POWER_UPDATE`) are registered per unit on `CDTL3.unitEventFrame` via `CDTL3:RegisterUnitEvents` (CDTL3.lua, above TurnOn) — not AceEvent — so raids don't wake the addon for every member. Handlers keep the AceEvent signature `(event, unit, ...)`; unregister them on that frame in TurnOff. `CDTL3:AnyLaneTracks(kind)` checks all lanes' primary/secondary tracking.

## Features added in 3.0.8 (where things live)
- **Per-entry bar colour**: saved entry `customColor` + `color`; copied to `f.data` in CreateCooldown; `private.GetBarFGColor` (Cooldown.lua) resolves entry colour → school → class → frame. Filters controls from `private.AddEntryColorArgs` (Options.lua), which updates live cooldowns by type + name/itemName. `private.FilterEntry(t)` = the entry being edited (or `CDTL3.custom` while adding).
- **Spell schools**: only the combat log exposes them. `CDTL3:RecordSpellSchool(name, mask)` (CDTL3.lua, above the CLEU handler) caches per spell name, writes `school` onto saved entries/live data once; `SaveNewEntry` picks up an already-seen school. School pickers (`private.AddSchoolColorArgs`) and the bar frames' fgSchoolColor toggle are hidden by `private.NoCombatLog()`.
- **Bar textures**: **always** set bar/background textures with `CDTL3:SetBarTexture(region, name)` (Media.lua) — it handles LSM names and modern atlases (`CDTL3.barAtlases`, filtered by `C_Texture.GetAtlasInfo`; StatusBars take atlas names directly in `SetStatusBarTexture`, Textures use `SetAtlas`). Texture dropdowns use `CDTL3:GetBarTextureList()`, not `AceGUIWidgetLSMlists.statusbar`; atlases are deliberately NOT registered with LSM (other addons would list broken entries).
- **Presets / copy**: AceDB stores only non-default values, so anything that copies settings must merge defaults and stored values (`Effective` in Presets.lua) and write into the existing tables. Presets change looks only (textures, bg colour, borders, fonts, class-colour toggles); "CDTL3 Classic" restores exactly those fields from each container's own defaults. `KEEP_ON_COPY` = name, enabled, posX/posY/relativeTo, editMode.
- **Edit Mode**: per-layout positions in `s.editMode[layoutName] = {point,x,y}`; `posX/posY/relativeTo` are always kept in sync as the plain position. Entering Edit Mode calls `ToggleFrameLock(true)` (quiet: no popup/chat) and re-locks on exit.
- **Options generators** (Options.lua top): `private.AddBorderArgs(args, base, borderFn, refreshFn [, firstOrder])`, `AddCopyArgs`, `AddStyleArgs`, `AddSchoolColorArgs`, `AddEntryColorArgs`, `TrackingValues`, `ValidateSeconds`; since 17 Nov 2026 also the text slots (`private.TEXT_LISTS` + `AddTextArgs` / `AddTextSection`: bar, lane icon, Ready icon, lane default and custom texts), `GetFrameAppearance` (bar and Ready frames' Appearance tab), `AddIconArgs` (lanes' and Ready frames' Icons tab), `GetNameOption` / `GetEnabledOption` / `GetGrowOption` / `GetAnchorPointOption` and the one `ANCHOR_POINTS` table. ## Conventions
- **Never** append a `Co-Authored-By` trailer to commits. Tabs for indentation (match the existing file).
- **Never put any AI/assistant attribution or session reference anywhere**: no `Claude-Session:` lines, claude.ai session links, "Generated with …" footers or tool names in commit messages, PR titles/bodies, changelogs, release notes, README, in-game text or code comments. Commits are authored as the maintainer (repo git config `user.name`/`user.email`).
- **Release notes come from `CHANGELOG.md`** (`.pkgmeta` `manual-changelog`), not from git commit messages. Update it before tagging a release. **The CurseForge and Wago project descriptions each hold a hand-kept Changelog section the packager never touches** — after every release, paste the new version's section into both (CurseForge: Manage Project → Description; Wago: the addon's dashboard). Both fell behind at 3.0.10/3.0.11. `.pkgmeta` also keeps `CLAUDE.md`, `README.md`, `docs/` and `.github/` out of the package.
