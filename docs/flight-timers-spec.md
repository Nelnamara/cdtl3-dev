# Flight timers — scope (10 Nov 2026)

The owner's ask: "IS there a way we can track flight timers? There used to be an addon that did this in the lich king era. Flight paths are all well established..." and "The whole point is to add it to cdtl". InFlight did this in Wrath: it timed each route once, then showed a countdown on later flights.

## What the player sees
- **Take a flight path and a countdown starts.** An icon named for the destination ("Thunder Bluff") with the faction's flight icon counts down to landing in a lane and a bar frame. On landing it goes to the ready frame with the usual ready sound.
- **Exact after one flight.** A route any character on the account has flown counts down from the last real time. A route never flown counts down from an estimate built from the game's route data, in the dimmed text CDTL3 already uses for estimates. Landing records the real time.
- **Every client**: Retail, MoP Classic, TBC Anniversary, Classic Era and WoW: Forever.
- **Settings** (Global tab › *Flight timers*): on/off (on by default), lane, bar frame and ready frame (lane 1, bar frame 1, ready frame 1, like spells), and *Forget learned flight times*.
- **Always visible in flight**: *Hide out of combat* doesn't hide it (nobody is in combat on a flight), and *Hide Long Timers* doesn't hide it, since a flight runs past a lane's Max Time. Beyond Max Time the icon waits at the lane's far end.
- **Logout or disconnect mid-flight**: on login, if still on the flight, the countdown resumes at the right point.
- **Retail's early landing** (or any flight that ends at the wrong place) ends the timer without saving a time.

## How
- **Route**: `TAXIMAP_OPENED` caches every slot's name, type, node ID (`C_TaxiMap.GetAllTaxiNodes`, matched by `slotIndex`) and hops (`GetNumRoutes` / `TaxiGetNodeSlot`). A post-hook on `TakeTaxiNode(slot)` (`hooksecurefunc`, nothing of Blizzard's replaced) picks the route from the cache. Node IDs aren't localized, so a time learned on an English client works on any language.
- **Timing**: takeoff is when `UnitOnTaxi("player")` turns true (`PLAYER_CONTROL_LOST`), and landing is when it turns false (`PLAYER_CONTROL_GAINED`). None of these calls or events are on Midnight's hidden list (checked against Blizzard's UI source for Retail and Forever, 10 Nov).
- **Saved data**: learned times in AceDB `global` (account-wide), per client and per `from-to` node pair. The flight in progress goes in `char` (server time) so it can resume after a login.
- **Estimates**: `FlightData.lua`, generated by a repo tool `tools/flight-data` from wago.tools `TaxiPath` and `TaxiPathNode` per client in `tools/spell-list-check/builds.json` (Forever: 328 routes, 101 flight points). It stores each route's length in yards and its stop delays. Estimate = the sum of each hop's length ÷ taxi speed, plus delays. The speed starts at a constant measured on the owner's first flights and is re-fitted from every learned flight.
- **CDTL3 side**: a new entry type `flights` created through `CreateCooldown`, counting down like Custom timers. Combat timers are untouched.
- **Harness**: `tools/tests/flights.lua` (taxi stubs) covers the route pick, learning, estimate, resume, early landing and both hide settings. The generator gets its own check like `spell-list-check`.

## As built (test build 1, 10 Nov)
- **Taxi speed** starts at 30.3 yd/s: flight paths run at about 433% of the 7 yd/s run speed (the owner: "its a multiplier on the standard run/mount speeds"). Each learned flight with route data refits it, per client.
- **Route data** (`tools/flight-data`): Era 289 routes, Forever 313, TBC 513, MoP 1844, Retail 4547. Flag `0x1` on a TaxiPathNode point marks the jump after it (skipped), as does a continent change. `Delay` is in seconds and only appears on boat and zeppelin stops. Forever: Thunder Bluff → Crossroads is 4752 yd (about 2:37), and Moonglade (Horde) → Thunder Bluff is 16313 yd in one hop (about 9:00).
- **Guards**: a flight under 60% of its saved time doesn't overwrite it, and neither does an early landing or a flight resumed after a login (taken to pause while logged out). A `/reload` keeps the clock running and still saves. A picked route that hasn't taken off within 10 s is dropped. Turning the option off mid-flight ends the countdown.
- **Not in the spec, decided while building**: the flight countdown waits at 0.1 s if it runs out before landing, so it reaches the ready frame on landing rather than early. A route the data lacks uses straight lines between the map's flight points × 1.2 (dimmed like any estimate). With neither, there's no countdown, but the time is still learned.
- **Harness**: `tools/tests/flights.lua` on all six TOCs.

## Walk (his Forever Druid)
Fly a route for the first time (dimmed estimate, then the real time saved), fly it again (exact), and log out mid-flight and back in (it resumes). Then the settings toggles.
