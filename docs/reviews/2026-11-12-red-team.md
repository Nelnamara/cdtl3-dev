# Red team, 12 Nov 2026

Four reviewers read the code looking for bugs, then a second reviewer tried to disprove each finding. 34 held up, several narrowed. Two were dropped: the Long buffs scale button has no confirm because your build 2 spec asked for one click, and a suspected Autohide blink couldn't be shown. Go means worth fixing; nothing changes until you say.

Marks live on the CDTL3 Review List (https://claude.ai/artifact/WMUgWuZnMD8anEq5jtjqSL).

## Can lose or break saved settings

### 1. Importing with All Settings and Data empties every Filters list

*Loses settings · All clients · Helpers.lua:1750 · Held up*

Import a friend's Settings Only string but pick All Settings and Data, and every Filters list is emptied with no message: Custom timers and per-spell tweaks are gone, for every character on that profile. The All branch only checks the five settings keys; the Cooldown Data branch already refuses the same string.

### 2. Clear Individual Settings also wipes the alts' copy

*Loses settings · All clients · Options.lua:3491 · Held up*

Filters › entry › Clear Individual Settings removes the entry by name without checking which characters use it. On the shared Default profile the alts' Custom CD Time, lane and Ignored go too, and a Custom is gone for everyone. Defaults › Clear Settings already keeps other characters' entries.

### 3. Reset Profile and Copy From clear every character's Filters data, no confirm

*Loses settings · All clients · Options.lua:6955 (stock Ace3 Profiles tab) · Held up, narrowed*

No confirm on these two is how Ace3's stock Profiles tab works in every addon. What makes it worse here: all Filters data (spells, Customs, Custom CD Times) lives in the profile, on a Default profile every character shares, so one misclick clears it for all of them. Only Delete asks first.

### 4. After Clear Quest Items or a profile switch, Filters keeps the old entry open

*Edits the wrong entry · All clients · Options.lua:1514 · Held up, narrowed*

The selection isn't reset. Its controls then do nothing or, because entries are matched by name, quietly change another character's copy of that entry.

### 5. A hand-edited import string can break the profile for good

*Lua errors · Rare · All clients · Helpers.lua:1767 · Held up, narrowed*

Import checks only the top level, then writes the profile. A string with a bad value inside (made by hand or by another addon) is saved and errors on every login, refresh or cast until the profile is reset. A truncated or mistyped string fails safely. The README says it validates before touching anything.

### 6. Stealth or a paladin lockout can reset across two profiles

*Loses settings · Rare · Era, TBC, Forever · Helpers.lua:329 · Held up, narrowed*

The built-in spell data table is saved into the profile itself rather than a copy. A rogue who casts Vanish before Stealth on a second profile in the same session (or a paladin with Detect Shared CD, off by default) finds the first profile's Stealth settings back at defaults after logout.

## Wrong on screen

### 7. A switched-off lane makes its cooldowns vanish for their last 2 minutes

*Wrong on screen · All clients · Cooldown.lua:1129 · Held up*

Turn a lane off but keep its bar frame and, with Transition bars on (the default), each bar hides once under that lane's Max Time while the icon has nowhere to show. A bars-only setup loses every bar under 2 minutes. The 3.1.0 fix covered lane None only.

### 8. Early reset of a long cooldown: ready sound, no Ready icon

*Wrong on screen · All clients · Cooldown.lua:1681 · Held up*

Cold Snap, Preparation or Readiness used while a cooldown has more than 2 minutes left: the ready sound plays but no icon shows in the Ready frame. The icon was hidden for being over Max Time and nothing un-hides it. On Retail and Forever a combat estimate that ends early does the same.

### 9. The Frames unlocked box stays after a profile switch, and its Lock button unlocks

*Wrong on screen · All clients · Helpers.lua:1284 · Held up*

Switch from an unlocked profile (new profiles start unlocked) to a locked one: the box stays up over locked frames. Pressing its Lock button unlocks them, and `/cdtl3 lock` says they're already locked. A /reload clears it.

### 10. Filters › Custom › Add New: Enabled can't be unticked properly

*Wrong settings · All clients · Options.lua:3601 · Held up*

Any click on Enabled leaves the box showing ticked but saves the custom switched off, so it never appears. The getter falls back to Show by default when the value is false.

### 11. A Tracked Bars buff jumps to Ready mid-buff, then shows its full length

*Wrong on screen · Rare · Retail, Forever, in combat · CombatTimers.lua:267 · Held up, narrowed*

If Blizzard's bar stops updating for over half a second (UI hidden with Alt+Z), or Blizzard's bar pool hands the buff a different bar, the icon jumps to the Ready frame with the ready sound, comes straight back, and its text reads the full buff length (10:00 instead of 6:56) until the buff or combat ends. The icon's place and the bar stay right.

### 12. First use of a new item in combat shows a frozen 16:40 bar

*Wrong on screen · Retail, Forever · Cooldown.lua:1360 · Held up*

A never-seen trinket or potion used in combat gets a made-up 1000 s timer while its cooldown is hidden: a full bar reading about 16:40 until combat ends. Once per item, but every item on a fresh install.

### 13. Lane 1's GCD marker never shows in combat

*Wrong on screen · Retail, Forever · Lanes.lua:706 · Held up; one in-game check*

The GCD marker reads Moonfire's cooldown (8921), which is hidden in combat, so the marker hides for the whole fight. Spell 61304 is the game's GCD spell and is reported to stay readable; one `/dump` in game would confirm it.

### 14. A mistyped Trigger ID saves a blank Custom

*Wrong settings · Retail, Forever · Helpers.lua:815 · Held up*

Filters › Custom › Add New with an ID that isn't a spell: question-mark icon, no name, Save still works ("CUSTOM:  saved") and a blank row joins the list that never fires. Classic rejects the ID.

### 15. Ready › Highlight Duration does nothing

*Wrong on screen · All clients · Cooldown.lua:1878 · Held up*

A highlighted icon leaves the Ready frame after the Normal Duration (5 s), not the Highlight Duration (10 s). The setting is never read.

### 16. Secondary Tracking on lane 2 or 3 shows no marker until a reload

*Wrong on screen · All clients · Options.lua:4972 · Held up*

Setting Lanes › lane › Secondary Tracking from None doesn't refresh the lane, so the marker stays invisible until a /reload, a lock toggle or another lane change.

### 17. Vertical lanes: the secondary marker slides sideways off the lane

*Wrong on screen · All clients · Lanes.lua:969 · Held up*

On any vertical lane the marker (GCD by default on lane 1) moves along the horizontal, across the screen, and keeps its horizontal size.

### 18. TBC off-the-map flights count down under internal names

*Wrong on screen · TBC Anniversary (one case on Retail) · build.js:211 · Held up*

Quest and Halaa bombing flights read like "Quest - Horde Hellfire End", and the name sticks even after landing. Two quest points share a spot, so standing a few yards off can pick the other quest's route. The Duskwither Spire orb would get a 4 s countdown with a ready sound each time, if it's a real taxi. Taxi-map flights use the game's own names and are fine.

### 19. Lane custom texts with live tags sit frozen

*Wrong on screen · Rare · All clients · Lanes.lua:1111 · Held up, narrowed*

A lane custom text with a live tag such as `[cdtl.time.n]` only changes now and then, when an icon arrives or leaves. The per-frame update has been commented out since the first commit. Lane texts are off by default.

### 20. Hide out of combat: the last lane or bar frame can miss the pull

*Wrong on screen · Rare · All clients · Helpers.lua:291 · Held up*

With an earlier lane or bar frame switched off at login, the pull-start refresh uses the list position instead of the frame number, so the last one doesn't appear until a cooldown enters or leaves it.

### 21. Ready › Pinned Hide Time never hides the frame

*Wrong on screen · Rare · All clients · Ready.lua:89 · Held up*

With Auto-hide Frames on and a pinned icon ready, the Ready frame never hides after combat. The hide flag is set after the only check that reads it.

### 22. Override Autohide can't bring back an empty hidden lane

*Wrong on screen · Rare · All clients · Lanes.lua:932 · Held up*

With Autohide and Override Autohide on, an empty lane that faded out doesn't come back when health or power drops, because the tracking that sets the override only runs while the lane is visible.

### 23. A Ready frame switched off still plays the ready sound

*Wrong on screen · Rare · All clients · Cooldown.lua:1873 · Held up*

After unticking a Ready frame, its sound keeps playing and icons wait in the hidden frame until a /reload.

### 24. A typed fraction in Split Count puts every icon at the lane's end

*Wrong settings · Rare · All clients · Options.lua:4502 · Held up*

The slider has no step, so typing 1.5 saves 1.5; the lane only handles exactly 1, 2 or 3 splits, so the markers vanish and every icon sits at the far end. Dragging snaps to whole numbers.

### 25. Edit Mode shows and saves clamped sizes

*Wrong settings · Rare · Retail, MoP, TBC, Forever · EditMode.lua:127 · Held up, narrowed*

Edit Mode's sliders stop at 200 px for lane height and start at 8 px for icons and 20 px for widths. A lane thicker than 200 px shows 200 in Edit Mode, and one nudge saves the limit.

## Release and tools (yours only)

### 26. Run workflow by hand would publish to CurseForge and Wago

*Release risk · release.yml:3 · Held up, narrowed*

The release workflow can be started by hand from any branch. CurseForge and Wago uploads don't need a tag, so from main it would re-upload 3.1.1, and from an untagged branch like cdm-probe it would publish a public alpha, with no boop. Only you can start it.

### 27. Release actions use moving tags while holding the upload keys

*Release risk · Low · release.yml:16 · Held up*

BigWigsMods/packager@v2 and actions/checkout@v4 aren't pinned to a commit, and the job holds the CurseForge and Wago keys. @v2 is the packager's recommended tag and pinning would freeze its fixes, so this is hardening only. The 3.1.1 run log also warns checkout@v4 runs on a Node version being retired.

### 28. spell-list-check misses hotfixes to a build it already downloaded

*Tool gap · check.js:43 · Held up, narrowed*

Cached tables are reused unless `--refresh` is passed. That's documented, but the after-a-patch steps and the CLAUDE.md hotfix note don't say a hotfix on an already-cached build needs it (Forever's build was cached on 10 Nov).

### 29. spell-list-check passes a spell Blizzard took off its class

*Tool gap · check.js:236 · Held up, narrowed*

It checks that each listed spell exists, not that the class still has it. Forever's Lava Burst removal was caught only because its cooldown changed too. Nothing breaks in game; a stale entry just stays listed.

### 30. FlightData --check calls every file changed on this PC

*Tool gap · Windows checkout · .gitattributes · Held up*

Git's line-ending setting on this PC rewrites the files, so `build.js --check` reports all five FlightData files different on every line and real drift can't be seen. Regenerated with line endings stripped, all five match: the data is current.

### 31. Classic aura and combat-log tracking lean on Blizzard's deprecated functions

*Future risk · Era, TBC, MoP · Helpers.lua:1044 · Held up, narrowed*

On the Classic clients `UnitAura` and `CombatLogGetCurrentEventInfo` now live only in Blizzard's deprecation files, which load by default. Nothing breaks today; if Blizzard drops those files, buff, debuff and swing tracking would stop with no error.

## Speed and memory

### 32. Grouped stacking does far more work than it needs

*Slow · Rare · All clients · Lanes.lua:499 · Held up, narrowed*

With stacking on in Grouped style, the stack loop runs inside the icon loop, so the work grows much faster than the icon count (40 icons: about 860 frame-level calls per pass instead of 40). Stacking is off by default; nothing visible at normal counts.

### 33. Combat timers make new tables every frame

*Memory churn · Retail, Forever, in combat · CombatTimers.lua:548 · Held up, narrowed*

Each riding icon builds a few small tables and a closure every frame, roughly 0.1 to 1 MB per second with 5 to 10 icons. Nothing shows in play; an addon memory monitor would show CDTL3 churning in combat.

### 34. Test mode lists each test cooldown twice and leaks frames

*Memory · Test mode only · Helpers.lua:610 · Held up, narrowed*

Each Create in the Test Panel adds new frames (up to 20) that are never reused until a /reload, and lists each cooldown twice. No visible effect.
